# دليل المنتجات والتوفر اليدوي — تحقق محلي

إنجاز جزئي بالمرحلة 2، وليس جاهزية التطبيق كله أو CI النهائي.

- استُعمل `ProductsView` و`ProductDetailModal` القائمان بخاصية وضع افتراضية
  full؛ الجذر الحقيقي سيوصل الوضع المتحقق صراحةً في خطوة لاحقة.
- عند OFF اختفت قيم المخزون والتكلفة والأرباح والاستلام وفلاتر المخزون
  من دليل المنتجات وتفاصيله. بقي الاسم والباركود والأسعار والطرد والنكهات
  والصور والتحرير. لم تتغير استعلامات full أو العقود/الصلاحيات القائمة.
- `ManualAvailabilityPanel` يقرأ الأساسي والنكهات في مجموعة واحدة. المفاتيح
  تعرض العلم الخاص بكل صنف، وبيان التوفر الفعلي يوضح أثر الأساسي/الإخفاء.
  لا يُغيَّر `is_active` أو مخزون أو سعر أو تكلفة.
- التغيير يرسل revision المقروء مرة واحدة فقط. عند فقدان الرد تُخفى مفاتيح
  الكتابة حتى قراءة صريحة جديدة؛ لا retry ولا افتراض أن التغيير فشل أو نجح.
  اختلاف المستخدم/مجموعة الأصناف يبطل الرد السابق. الأدوار الأخرى لا ترى
  المفتاح، والخادم يبقى حارس owner مستقلاً.

النتائج: 62 وحدة، typecheck، وstrictlint بلا تحذير. 40 حالة Chromium/WebKit
ناجحة بلا retries: 32 حالة المنتجات والنوافذ القائمة + 8 جديدة، تشمل
العائلة والنكهة، فقدان الرد واسترجاع revision الصحيح، تغيير الوضع، وعدم
رؤية غير المالك للمفاتيح، وغياب مؤشرات الربح والمخزون عند OFF.
