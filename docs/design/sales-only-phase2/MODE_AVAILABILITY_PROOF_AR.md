# قراءة الوضع والتوفر اليدوي — طبقة مشتركة قيد الربط

ملفات المتصفح الجديدة لم تُربط بـApp بعد؛ لا نعلن اكتمال الواجهة. قارئ الوضع يقبل version/boolean صريحين فقط، أو404/PGRST202 المحدد لدالة الوضع الغائبة على219 فيعني full قديم بلا ميزة مركبة. الشبكة والرد المشوّه والمتناقض لا تُفترض full. اختبارات تقارن هذا العقد مع Edge القائم.

المزوّد الجديد يحفظ هوية المستخدم وجيل القراءة: طلب مستخدم قديم لا يكتب على جلسة جديدة، وقراءة ما قبل تغيير الوضع لا تتغلب على القراءة التالية، والخروج يبطل المنتظر. فشل التحديث يحتفظ بالوضع السابق للعرض حتى لا تضيع السلة، لكن verified يصبحfalse لوقف بداية عملية جديدة عند ربط الواجهة. لا default تشغيلي إذا غابالمزوّد؛ خطأ صريح. هذا لا يغيّر استرجاع المحاولة المعلقة من مسارها المحفوظ.

التوفر اليدوي نفس جدول phase1 ونفس setter ومقارنة revision. أضيف غلاف للمالك يشترط OFF وقارئ bounded لـ200UUID يعيد متوفر/غيرمتوفر ومراجعتها والتأثير الموروث من العائلة، لا مخزوناً وهمياً ولا تكلفة. العميل يرفض missing/duplicate/substituted UUID والرد المتناقض، ويسقط أي حقول إضافية. تعديل واحد فقط بالمراجعة الأصلية؛ فقدان الرد يفرض قراءة، دون retry أو تخمين revision جديد. نقاط prototype القديمة مسحوبة الصلاحية في التركيب الكامل؛ لا ACL لدالة219 تغيّرت.

جُمعت مكوناتSQL المحجورة في phase2PrototypeSql، لا executor ولا URL فيه؛ التنفيذ يبقى حصراً في runner حاويته المملوكة والمعزولة219/180. لا migration فعالة.

الإثبات الفعلي: العميل الحالي إلى PostgreSQL، إيقاف العائلة يؤثر على النكهة دون الكتابة فوق علمها، revision قديم مرفوض، إعادة العائلة ممكنة بالمراجعة الصحيحة، وanon/service_role/مدخلprototype ممنوعون. بعد التفعيل الكامل يرفض setter الجديد تعديل حالةOFF. إعادة اختبارepoch كلها نجحت مع636/628 محفوظة وintegrity0 وnetwork0 والتنظيف. قياس6صفوف مع إعادة متزامنة نحو679.612ms؛ ليس إثبات حجم820.
