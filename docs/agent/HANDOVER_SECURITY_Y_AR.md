## ما تغيّر

| البند | التنفيذ والتحقق |

| ي2 | سُحبت TRUNCATE وREFERENCES وTRIGGER من PUBLIC وanon وauthenticated على جميع جداول public، مع بقاء منح القراءة والكتابة الحالية وservice_role الأخرى كما في المرجع. |
| ي3 | التتبع برقم الطلب والهاتف للزائر محدود بـ30 محاولة للهاتف المنسق و120 للمصدر خلال عشر دقائق. العدّاد خاص ويحفظ معرّفات مجزأة فقط. الرد العربي لا يكشف وجود الطلب. نجح التزامن بجلستين وحالات JWT الغائب والفارغ والمتناقض. قارئ رمز التتبع لم يتغيّر. |
| ي4 | أُغلق التنفيذ المباشر لدالتي محفّز النكهات. ثبت أن محفّز الوراثة يعمل بعد السحب عند تحديث فعلي بحساب authenticated. |
| ي5 | لا يستطيع الزائر سرد أسماء الصور. تبقى الصورة قابلة للقراءة برابطها العام. نجح الرفع والتعديل والحذف داخل مجلد الموظف للأدوار الأربعة المسموحة، ورُفض الكاشير والحساب بلا دور والرفع إلى مجلد آخر. |

| ي7 | ملفات deno.json وdeno.lock مجمّدة لكل دالة Edge، مع supabase-js 2.110.8 وweb-push 3.6.7. نجحت الرسوم الخمسة ورُفض رسم غير مسجل. أجسام الدوال لم تتغيّر. |
| ي8 | ثُبّت search_path لحارس إلغاء POS. بقي pg_net في مكانه كما أنشأه Supabase، مع توثيق السبب؛ لم تُنقل اعتماديات الإشعارات. |

## الأدلة المحلية

- ترقية 213 حرفياً: 74 حالة، تشمل رفض 60 استدعاء للمداخل القديمة والمحفّزات عبر عشر فئات أدوار، بلا تغيير صفوف أو تسلسلات.
- اختبارات الإدارة 1408 والمتجر 197، وTypeScript وlint الصارم وبناء التطبيقين وفحص SEO المعزول: ناجحة.
- مجموعة المتصفح الأساسية: 395 ناجحاً و59 حالة شرطية تاريخية، دون فشل أو تذبذب؛ وتحديث PWA: أربع حالات على Chromium وWebKit دون طلبات خارجية.
- قراءات الواجهة: 154 استعلاماً فعلياً ناجحاً. جرد RPC يغطي 537 استدعاء مع عشر حالات رفض دور متوقعة.
- المرجع: 175 migration و556 دالة و13 جدول Realtime، وصفر فروق بين البناء الجديد والترقية التدريجية.
- أمر المالك على قاعدة محلية: تطبيق وتسجيل 213، وإعادة تشغيل بلا كتابة، ورفض فروق ACL للدوال والجداول وsearch_path، ثم تحقق صارم ناجح بلا كتابة.
- Storage عبر HTTP والتصفير: ناجحان؛ صفر فروق كتالوج، مع بقاء المالك وMFA وحذف حسابات وصور التجربة. اعتمد حارس التصفير سياسة metadata المحددة للسقف 213 فقط؛ بقي رفض الاعتماديات الأخرى والسقوف الأقدم.

توقفت محاولة Windows عند أمر CLI لتسجيل 073 بعد نجاح SQL. لم يحتفظ التقرير الأول بتفاصيل كافية لتحديد السبب. نجح التكرار التشخيصي كاملاً بنفس الشروط والمهلات وassertions، وثبت عكس تحويلاته إلى الملف الأصلي حرفياً. نجح أيضاً مسار التصفير الأصلي داخل FULL CI للنسخة `4e2da95`؛ لا ندّعي إصلاح سبب الخروج العابر غير المحدد.

التفاصيل في `HANDOVER_SECURITY_Y_LOCAL.json` و`HANDOVER_SECURITY_Y_DB.json`. نجح push النسخة البرمجية `4e2da95` في FULL44 وفحص الأسرار. يتطلب القبول النهائي نجاح FULL44 وفحص الأسرار على آخر SHA للـpush والـPR؛ هذه الأرقام المحلية لا تحلّ محل ذلك.

## حدود تدقيق المكتبات
