# دليل الصيانة والمتابعة — النواصرة

للمطوّر الذي يستلم المشروع. تاريخ المرجع: 2026-10-12، قاعدة الاختبار حتى **001–138**.
هذا الدليل لا يعطي إذناً بالنشر أو الاتصال بالإنتاج. المشروع ما زال قبل التسليم؛
مشروع فرانكفورت والتفعيل ونقل مهام المحل وأرصدة البداية تحتاج خطوات معتمدة منفصلة.

## 1. أين الحقيقة وأين الملفات؟

PostgreSQL هو مصدر حقيقة المال والمخزون والذمم وحالة الطلب. الواجهة تعرض وتطلب
الإجراء، ولا تعيد حساب حقيقة محاسبية أو تعالج رصيداً بتعديل صف مباشر.

| المكان | وظيفته |
|---|---|
| `src/features/` | شاشات الإدارة: البيع، الطلبات، العملاء، المخزون، الموردون والصندوق |
| `src/services/supabase/` | عقود RPC والقراءة، والتعافي من النتيجة المجهولة |
| `src/stores/` و`src/hooks/` | حالة العرض والتحميل والجلسة؛ ليست سجلاً مالياً |
| `src/components/ui/` و`src/styles/design-tokens.css` | المكونات المشتركة وألوان `--nw-*` |
| `customer-web/src/` | المتجر والإتمام والتتبع؛ له فحوصه وحزمة بناء مستقلة |
| `supabase/migrations/` | تاريخ قاعدة البيانات، بالترتيب الرقمي |
| `supabase/functions/` | Edge Functions، ومنها `submit-guest-order` و`admin-ai-assistant` |
| `tests/` و`customer-web/tests/` و`e2e/` | وحدات وعقود ومتصفح؛ راجع مسار الاختبار الفعلي في package.json |
| `scripts/testing/` | DB معزولة، fixtures، إثبات الأرقام، خوادم الفحص المعزولة |
| `scripts/backup/` و`scripts/offsite-backup/` و`scripts/monitoring/` | النسخ والتحقق والتنبيهات التقنية |

ابدأ بـ[PROJECT_OVERVIEW](agent/PROJECT_OVERVIEW.md)، ثم
[قواعد العمل](agent/OPERATING_RULES.md)، [حالة المشروع](agent/project-state.json)،
[المهمة الحالية](agent/ACTIVE_TASK.json)، و[القرارات المعتمدة](agent/OWNER_DECISIONS.md).
النصوص القديمة في المحادثات و`docs/HANDOFF.md` تاريخية، لا إذن ولا إثبات حالة حية.
عند تعارض ملخص قديم، راجع القرار الأحدث والسقف في project-state وGit والأدلة.

## 2. بداية جلسة آمنة

في PowerShell من جذر المشروع، على Node المطابق لـCI وبتبعيات lockfile:

```powershell
npm.cmd ci
npm.cmd --prefix customer-web ci
npm.cmd run agent:resume
npm.cmd run agent:preflight
git status --short
```

تثبيت التبعيات لا يجري أثناء تشغيل خادم فحص أو متصفح. إذا كشف resume اختلافاً
غير معتمد، توقف؛ لا stash/reset ولا حذف تعديلات لتجاوز الحارس. كاتب واحد لكل
worktree، والمراجع قراءة فقط. لا تفتح ملف أسرار لتضمينه في تقرير أو سجل.
للتطوير المحلي فقط: `npm.cmd run dev`؛ إعدادات الاتصال المعزولة من المثال المعتمد،
ولا تنسخ إعدادات الإنتاج تلقائياً. خوادم QA المعزولة لا تستخدم HMR/watch.

## 3. الفحوص وبوابة التسليم

قبل **كل commit**:

```powershell
npm.cmd run lint
npm.cmd test
npm.cmd --prefix customer-web run lint
npm.cmd --prefix customer-web test
git diff --check
```

`lint` يتضمن typecheck. شغّل أيضاً **كل** browser specs وDB runtimes المتعلقة
بالتغيير، Chromium وWebKit حيث ينطبق. على Windows تحت الحمل يمكن تشغيل كل
وحدات الإدارة بنفس التأكيدات تسلسلياً:

```powershell
npx.cmd tsx --test --test-concurrency=1 tests/*.test.ts
```

هذا اختيار محلي، لا تخفيف أو تعديل CI. لا تجمع DB ثقيلة مع خوادم فحوص أخرى.
ولا تعدّل أي ملف متتبّع، حتى ACTIVE_TASK، أثناء تشغيل الفحوص؛ السجلات خارج checkout.
عند تشغيل مستقل طويل احفظ السجل وexit code، وتابعه حتى ينتهي قبل التسليم.

أمثلة فحوص مرتبطة (ليست بديلاً عن اختيار كل المتأثر):

```powershell
npm.cmd run test:package-e:golden
npm.cmd run test:package-f:statement
npx.cmd playwright test e2e/package-f-customers.spec.ts --project=chromium --project=mobile-webkit
npm.cmd run test:monitoring:daily:runtime
```

راجع أسماء specs في `e2e/` قبل الأمر. Golden day يصالح المال والمخزون والذمم
عبر المسارات الحقيقية. أي اختلاف رقم/صلاحية/كتابة = فشل، لا تغيّر التوقع لإخفائه.
قبل commit: stage ملفات محددة، ثم `gitleaks git --staged --redact --no-banner`؛
exit code يجب أن يكون **0**. افحص أيضاً الملفات الجديدة غير المضافة عند الحاجة؛
لا `git add -A` ولا force-push، ولا retries أو رفع مهلة لإخفاء فشل.

CI الكامل والأسرار على **نفس SHA** بوابة إلزامية، لا يكفي CI لوالد الـcommit.
المهام الحالية 21، لكن لا تثبّت العدد كحارس اكتشاف؛ يلزم نجاح جميع المهام.
Package F موزع على 3 shards، واتحادها مع core يُفحص ديناميكياً بلا نقص أو تكرار.

```powershell
npm.cmd run agent:verify-handoff -- --delivery
npm.cmd run agent:checkpoint -- --status PAUSED --next "الإجراء التالي المحدد أو انتظار مراجعة المالك"
```

الجودة المحلية الكاملة `npm.cmd run quality` للمحطات الكبرى قبل بناء مشروع
فرانكفورت/النشر، أو فشل CI غير مفهوم؛ ليست إعادة مطلوبة قبل كل تصحيح عادي.
الفحص الكامل على GitHub يبقى إلزامياً. راجع [VERIFICATION_GATES](agent/VERIFICATION_GATES.md).

## 4. إضافة migration بلا مخاطرة

1. اطلب موافقة على السبب والنطاق والقرار التجاري أولاً. هذه المهمة لم تضف 139.
2. اقرأ السقف الحالي ومرجع [الدوال الحالية](generated/DB_FUNCTIONS.md)، وتتبع المستدعين.
3. أضف الرقم التالي الفريد والمتصل؛ **لا تعدّل 001–138 التاريخية** ولا تتلاعب ببصماتها.
4. اكتب SQL كاملاً وصريحاً (`CREATE OR REPLACE FUNCTION` مسموح). لا تنسخ جسم
   دالة قديمة بواسطة `pg_get_functiondef` ثم `REPLACE`/`EXECUTE`، ولا تضف طبقة
   `_before_*` جديدة أو تعيد تسمية دالة إليها. الحفاظ على استدعاء قديم ليس إذناً بطبقة جديدة.
5. حافظ على المالك، وsearch_path مضبوط، وSECURITY DEFINER/INVOKER والصلاحيات
   والأدوار المقصودة. لا توسّع grants أو RLS عرضياً؛ اسحب PUBLIC/anon حيث يلزم.
6. أثبت قبل/بعد على قاعدة معزولة، وACL، وقراءة replay بلا كتابة، والذرية والأقفال
   إذا تغيّر writer، وتطابق JSON إن تغيّر قارئ. لا تعِد كتابة لقطة تاريخية بلا قرار.
7. حدّث السقف والبصمة **بالموافقة**، ثم أعد توليد المرجع واختبره. أي فهرس يحتاج
   EXPLAIN قبل/بعد وقياساً، لا تخميناً. النشر إلى الإنتاج خطوة مستقلة بإذن المالك.

حارس المستقبل ثابت بعد 138؛ لا ترفع حد الاستثناء كلما أضيفت migration.
يسمح `REPLACE` العادي للبيانات بلا تنفيذ ديناميكي، لكنه يرفض اجتماع
`REPLACE/regexp_replace` و`EXECUTE` في migration جديدة احتياطياً؛ استخدم صيغة صريحة.
التعليقات ليست SQL تنفيذياً. الحارس دفاع مساعد وليس بديلاً عن مراجعة SQL وصلاحياته.

## 5. مرجع الدوال: إعادة التوليد والتحقق

```powershell
npm.cmd run docs:db-functions
npm.cmd run docs:db-functions:check
```

الأول يعيد بناء DB **معزولة فقط** ويولّد `docs/generated/DB_FUNCTIONS.md` آلياً
بعد إيقاف الحاوية؛ الثاني يعيد البناء ويقارن الملف حرفياً ولا يكتب فيه.
يحتاج Docker وSupabase CLI من تبعيات المشروع. لا يقبل URL أو password أو مشروعاً حياً.
لا تشغله بالتوازي مع DB معزولة أخرى، ولا تعدّل migrations أثناء التوليد.
bootstrap يستخدم نسخة مؤقتة؛ توافق تنظيف034 فيها فقط لا يغيّر المصدر التاريخي.

لكل overload: التعريف الكامل الحالي، owner، security، volatility، config/search_path،
وEXECUTE grants الفعلية وACL الخام، ومصدر extension إن وُجد. يشمل public extensions؛
ملخّص EXECUTE يوسّع ACL الافتراضية فقط؛ لا يثبت صلاحية مستخدم بكل شروط الدور
الموروث والجلسة وMFA وRLS. إثبات ACL السلوكي يبقى عبر runtime لكل دور.
لا يشمل `auth` أو `storage` أو بيانات الأعمال. `pg_get_functiondef` هنا قراءة كتالوج
للتوثيق، **لا** ترقيع migration. المرجع ليس نسخة احتياطية ولا يُطبّق كملف SQL.
اختبار سريع يربط أسماء ومحتوى كل migrations ببصمة الملف؛ CI يعيد استخراج كل
الدوال ويطابق الملف كاملاً. لا تعدّل التعريف في Markdown يدوياً لتجاوز الفرق.

## 6. النسخ والاسترجاع

للمشغّل المعتمد، فحص الحالة المحلي: `npm.cmd run backup:status` و
`npm.cmd run monitoring:status`. لا تشغيل نسخة/تعديل إعدادات/اعتماد أسرار أثناء مراجعة كود.
النسخ الليلية ERP مشفرة `.nwb` مع manifest وSHA-256؛ DPAPI خارج Git، وR2 نسخة
خارجية مستقلة. وجود ملف لا يثبت صحة النسخة: يلزم آخر نجاح حديث، التحقق من checksum
وفك التشفير، ونجاح restore drill معزول. فشل R2 لا يمحو نجاح النسخة المحلية.

نتائج Scheduler: `0` نجاح، `267009` جارٍ ضمن حدّه، `267011` لم يعمل بعد.
الجاري ليس نسخة ناجحة؛ تجاوزه حد الزمن أو غياب نسخة حديثة يبقي التنبيه.
راجع [الحدود الجديدة](operations/OPERATIONAL_STABILITY.md) قبل تفسير README تاريخية.
الحارس الحالي يراجع عمر النسخة 36 ساعة؛ ارفع مشكلة النسخة القديمة ولا تحذف آخر نسخة سليمة.

بإذن مشغّل الصيانة: `npm.cmd run backup:verify` يفحص الأرشيف، و
`npm.cmd run backup:restore-test` يسترجع إلى حاوية معزولة؛ المطلوب `ok=true`
و`liveSupabaseTouched=false`. restore drill دوري 90 يوماً، ولا يغني عن بروفة
محددة قبل تغيير خطير. لا استرجاع للإنتاج من هذا الأمر ولا من المرجع المولّد.

**حدود مهمة:** الأرشيف المنطقي يغطي public والملفات المعروفة للصور؛ لا يحتوي
Auth users/passwords/MFA أو كامل auth/storage schemas. dump الأدوار يُتحقق منه
ولا يُطبق آلياً في drill؛ grants/RLS تُبنى من migrations. فقدان جهاز المحل لا
يعني فقدان DB السحابية، ولا يبرر الكتابة فوقها. نسخة DPAPI لا تنتقل لجهاز جديد؛
احتفظ بنسخة استعادة مستقلة لعبارة التشفير لدى المالك، لا داخل المستودع.

الاسترجاع الحقيقي: موافقة، هدف معزول، تنزيل الأرشيف المطابق وحسم cutoff، تحقق
المخطط والبيانات والأرقام، ثم Auth/UUID mapping وMFA وStorage وEdge وإعداداتها،
ثم اختبار وصلاحيات ومصالحة قبل أي cutover. لا تخمّن هوية عميل أو تعدّل Auth internals.
التفاصيل: [backup README](../scripts/backup/README.md)،
[off-site README](../scripts/offsite-backup/README.md)، [runbooks](operations/MONITORING_RUNBOOKS.md).

## 7. التنبيهات ومتى نتوقف؟

| التنبيه | المعنى والإجراء الأول |
|---|---|
| Integrity / CRITICAL | فرق أدلة مالي أو مخزني؛ أوقف العملية المتأثرة وصالح قراءة فقط، لا تعدّل الرصيد مباشرة |
| Backup / R2 | نسخة قديمة/فاشلة أو تحقق ناقص؛ راجع السجل والأرشيف، لا تحذف نسخة سليمة |
| Supabase daily read | طلب قراءة فشل؛ تحقق من توفر المشروع والاتصال، لا تفترض فساد البيانات |
| Database size | حد التنبيه 400,000,000 bytes؛ راجع النمو والتخطيط مع المالك، لا تحذف حركات |
| Public Uptime | HTTP ليس 200 أو ترويسة حماية مفقودة؛ راجع الخدمة والترويسات |
| n8n / outbox | تأخر تسليم رسائل؛ راجع الناقل والـevent key، لا إرسال مزدوج يدوي |
| Deployment/source mismatch | قارن release الذي يؤثر على التطبيق، لا docs HEAD وحده؛ لا نشر من شجرة متسخة |

القناة التقنية للمطوّر لا تحمل أسماء/هواتف/عناوين/مبالغ عملاء. القناة التجارية
منفصلة. التكرارات مقيّدة والتعافي يُرسل من الفحص؛ لا تحذف incidents لإخفاء الإنذار.
`Unknown` ليس Healthy. تقرير أدلة لم يُفحص منذ24 ساعة يستلزم متابعة.
عند بيع UNKNOWN لا تعِد البيع بمفتاح جديد: استرجع المحاولة، أو أثبت الخادم عدم
وجود أثر قبل الإلغاء المسموح. لا تمسح دليل التعافي يدوياً.

الفحص اليومي الجديد معطّل افتراضياً حتى تفعيل فرانكفورت في Phase7؛ لا تدّع أنه
يعمل على البيئة الحية الآن أو أنه يضمن عدم إيقاف الخطة. نقل الجهاز/تعطيل جدول
GitHub Uptime عند private/تفعيل التنبيهات إجراءات تشغيل مستقلة، موثقة في
[OPERATIONAL_STABILITY](operations/OPERATIONAL_STABILITY.md).

## 8. أين القرار وكيف تسلّم؟

أي قاعدة جديدة للمال أو الخصم أو الجرد أو الدور أو الإغلاق: سجّل سؤالاً للمالك
في [OWNER_DECISIONS](agent/OWNER_DECISIONS.md) وانتظر؛ لا تستنتج سياسة من UI أو fixture.
التحسينات المؤجلة في [POST_DELIVERY](agent/POST_DELIVERY.md). أرصدة البداية/Excel
مؤجلة لآخر خطوة قبل التشغيل، وليست جزءاً من هذه المهمة.
سجل الأثر والاختبارات والـSHA في docs/agent، وحافظ على ACTIVE_TASK قصيراً للخطوة
الحالية. لا IDLE قبل commit العمل. تسليم صحيح = بوابات محلية + Gitleaks0 +
commit/push معتمد + CI على نفس SHA + checkpoint + توقف للمراجعة.
