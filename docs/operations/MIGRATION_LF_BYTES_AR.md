# بايتات ملفات الترقية على Windows

تثبت `.gitattributes` ملفات `supabase/migrations/*.sql` على LF، حتى عندما يرث
clone جديد `core.autocrlf=true`. لا تغيّر هذه القاعدة أي migration أو بصمة معتمدة.

يفحص `npm.cmd run agent:preflight` البايتات الفعلية لكل ملف SQL، ويرفض وجود CR
برمز `MIGRATION_SQL_LF_BYTES_REQUIRED` مع أسماء الملفات. لا يحوّل الملفات ولا يصلحها
تلقائياً، ولا يستبدل المقارنة الحرفية التي تجريها أدوات الترقية.

الاختبار ينشئ مستودعاً مؤقتاً مستقلاً، ويعيد checkout مع `autocrlf=true`، ثم يثبت
بقاء LF. ويحقن CRLF في الملف المؤقت فقط، ويتأكد من الرفض وبقاء البايتات دون تعديل.
اختبارات 222 و223 و224 تحتفظ ببصماتها الحرفية، إلى جانب مطابقتها لملف الحالة وGit.

نسخة المالك الحالية لم يُعدّل إعدادها أو أي ملف منها ضمن هذا الإصلاح. لا يتضمن
هذا العمل `git add --renormalize` أو إعادة كتابة التاريخ أو تغيير الحراس والمراجع.
