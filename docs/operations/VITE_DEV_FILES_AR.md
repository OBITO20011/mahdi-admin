# حدود ملفات خادم التطوير

خادم التطوير للتطبيقين يبقى على loopback افتراضياً. لا تستخدمه للنشر، ولا تفتحه بنفق عام. لا تغيّر هذه الحزمة إصدار Vite المثبّت 6.4.4.

`scripts/environments/development-file-access.mjs` يحدد `server.fs.strict=true` وقائمة سماح: ملف الدخول و`src` و`public` والاعتماديات الفعلية فقط؛ وتضاف ملفات الوصل المشتركة للإدارة. عند وجود junction لـ`node_modules` نسمح بمجلد الاعتماديات نفسه، لا جذر المستودع الآخر. لا نسمح بجذر مساحة العمل أو مجلدات النسخ والوثائق.

الحظر يشمل `.env*` والشهادات والمفاتيح والأرشيفات المشفرة و`.git`. أنماطه تشمل نهاية الاستعلام أيضاً: في Vite6.4.4 قد يصل معرّف التحويل إلى فحص الحظر ومعه `?import&raw`، ولذلك حظر الامتداد وحده لا يكفي. [نشرة Vite الرسمية](https://github.com/vitejs/vite/security/advisories/GHSA-8g5g-mxqh-grgj).

`public/` مخصص للنشر العام، ويخدمه Vite بمسار خاص؛ لا تضع فيه أي سر أو نسخة احتياطية، ولا تعتمد على `fs.deny` لحماية محتوياته. ملفات `src` المسموح بها هي مصدر الواجهة، وليست مكاناً للأسرار أيضاً. أدوات الاختبارات المعزولة تستعمل قواعد مستقلة لمجلدات harness/cache المؤقتة؛ ليست أوامر خادم التطوير العادي.

التحقق المحلي بلا اتصال خارجي:

```powershell
node --import tsx --test tests/vite-file-access.test.ts
```

يشغّل إعدادَي Vite الفعليين على loopback بملفات وهمية: يرفض الملف خارج الجذر وملف البيئة والشهادة والأرشيف بـ403، مع وبلا استعلامات raw/inline؛ ويظل الدخول و`main.tsx` والوصل المشترك قابلة للتحميل. الاختبار السلبي المنفصل يثبت أن إعداد Vite القديم يعيد محتوى PEM الوهمي بـ200 عند إضافة الاستعلام. لا يقرأ أي ملف بيئة أو سر للمالك.
