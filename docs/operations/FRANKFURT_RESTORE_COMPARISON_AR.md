# تشخيص فروق المقارنة الصارمة للاسترجاع

الأساس main عند cbe22c5 بعد PR #28. وصلت محاولة المالك إلى `compare-data-catalog-acl`، لكن التقرير القديم لا يحدد المقارنة الفاشلة. لم نتصل بأي مشروع، ولم نقرأ مفاتيح المالك أو نفك أرشيفه، ولم ننشر.

## التغيير

لم يتغير معيار نجاح الاسترجاع: مقارنة الكتالوج بواسطة `logicalRestoreDifferences`، ثم التطابق الصارم للجداول والأدوار والعضويات والتاريخ والتسلسلات وStorage، بنفس ترتيب الرفض. لا دور مستثنى ولا ACL متجاهلة ولا تصحيح تلقائي للبيانات.

التشخيص أصبح `category=RESTORE_COMPARISON_FAILED`، ومعه `comparisonCode` من هذه القائمة الثابتة:

- `RESTORE_CATALOG_ACL_OWNER_SETTINGS_DIFFER`
- `RESTORE_TABLES_DIFFER`
- `RESTORE_ROLES_DIFFER`
- `RESTORE_MEMBERSHIPS_DIFFER`
- `RESTORE_HISTORY_DIFFER`
- `RESTORE_SEQUENCES_DIFFER`
- `RESTORE_STORAGE_DIFFER`

يُحفظ الكود عبر تقرير Restore وغلاف العملية والطرفية، دون محتوى expected/actual الخام أو SQL أو إعدادات خاصة.

## التقرير الخاص المنقّح

عند إخفاق المقارنة يُضاف `comparison-sanitized.json` إلى مجلد محاولة `restore-diagnostics` نفسه، قبل حذف الحاوية. تُطبّق حماية Administrators-only على Windows، مع قطع الوراثة قبل الكتابة. لا يُطبع محتوى الملف في الطرفية. إذا تعذّر الحفظ يظهر `logs.saved=false`، ويبقى كود المقارنة متاحاً؛ لا يُعلن نجاح حفظ لم يحدث.

يحتوي التقرير على:

- جميع أكواد المقارنات الفاشلة، وليس الكود الأول وحده.
- الكتالوج: نوع الكائن ومخططه واسمه وأسماء الحقول المختلفة، مثل owner وacl وconfiguration وdefinition وcolumns. لا قيم ACL أو تعريف دالة أو إعدادات.
- الجداول: الاسم والوجود قبل/بعد، وعدد الصفوف قبل/بعد، و`hashDifferent` بنعم/لا. لا بصمات ولا محتوى صفوف أو قيم أعمدة.
- الأدوار: الاسم وأسماء الخصائص المختلفة فقط، مثل super وconfig وlimit وuntil، دون قيمها.
- العضويات: أسماء الدور والعضو والمانح وأسماء الخصائص المختلفة، دون قيم الخصائص.
- التسلسلات: المخطط والاسم واسم الحقل المختلف، دون قيم التسلسل.
- التاريخ وStorage: وجود اختلاف وعدد العناصر فقط، دون أسماء ملفات أو metadata أو UUID أو بيانات صفوف.
- علامة `orderOnly` عند اختلاف ترتيب مصفوفة الأدوار أو العضويات أو التسلسلات فقط. يظل الرفض الصارم قائماً.

الأسماء غير الصالحة للعرض تُستبدل بعلامة ثابتة. حقول التقرير تُبنى من قوائم صريحة، ولا يُنسخ إليه كائن الفروق الخام أو before/after.

## تحليل الأسباب وحدود الإثبات

| الاحتمال | الاختبار المحلي | النتيجة وحدودها |
|---|---|---|
| أدوار يضيفها IMAGE، أو اختلاف flags وrolconfig | مصدر اصطناعي فيه supabase_etl_admin ودور مستقل، مع NOLOGIN وNOSUPERUSER وNOBYPASSRLS، وإعدادات statement_timeout وsearch_path وحد اتصال وعضويات | اجتاز التطابق الصارم. هذا ليس جرد أدوار فرانكفورت الفعلي؛ جرد 214 المحفوظ لا يتضمن pg_roles |
| رفع SUPERUSER المؤقت لإنشاء الامتدادات | حالة فرانكفورت الاصطناعية من PR #28، بمالكي الامتدادات وإصداراتها ومخططاتها السبعة، مع الأدوار الإضافية | تطابقت أعلام الأدوار والعضويات والكتالوج بعد الاسترجاع؛ لا استثناء أو تغيير مفترض |
| ACL وdefault privileges وملكية كائنات الامتداد | إضافة default privilege حقيقي في public إلى حالة الامتدادات الاصطناعية | نجحت المقارنة. لا يثبت ذلك تطابق كل امتياز في نسخة المالك التي لم نفكها |
| إعدادات postinit لـnet | اختبار INVOKER وconfig=null في الحالة الاصطناعية، والإعداد السابق لـCLI في الاختبار الأساسي | اجتازت الحالتان؛ لا تجاهل عام للإعدادات |
| تسلسل مستعمل وآخر غير مستعمل | إنشاء تسلسلين بقيم بداية مختلفة، واستعمال أحدهما قبل النسخ | اجتازت مقارنة pg_sequences.last_value الأصلية. صيغة v2 لا تلتقط is_called مباشرة، فلا ندّعي مقارنة حقل غائب عن source-evidence. لا تغيير لصيغة الأرشيف ولا طلب Backup جديد |
| صفوف auth وstorage والامتدادات التي تُنشأ تلقائياً | الاسترجاع إلى initdb خام ثم إنشاء المخططات والامتدادات، دون تشغيل خدمات Auth أوStorage | تطابقت أعداد وبصمات جميع الجداول الـ141 وبيانات Storage في التجربة غير الفارغة. لا حذف صفوف تلقائي ولا تجاهل جدول |

**لم تُعد التجربة الموسّعة إنتاج إخفاق نسخة المالك.** لذلك لا تتضمن هذه الحزمة إصلاحاً تخمينياً لأدواره أو ACL أو بياناته. إعادة Restore بالتشخيص الجديد ستحدد المقارنة والكائن الفعليين.

إذا كشف التقرير فرقاً حقيقياً في الصفوف أو الأرصدة أو المخزون أو الذمم، نتوقف ونبلغ المالك؛ لا نصحح البيانات أو نتجاهل الفرق. وإذا ثبت أن السبب من بيئة الاسترجاع، يجب أن تكون معالجته محددة بالاسم ومبررة ومختبرة.

## الإثبات

- اختبارات لكل كود من السبعة، وللدور الإضافي أو المفقود، ولرفض كود تشخيص مزوّر، ولمطابقة قرارات القبول والرفض مع المقارن السابق. القيم الاصطناعية الخاصة في SQL والبصمات والإعدادات وStorage والتسلسلات لا تظهر في التقرير.
- استرجاع أساسي، ثم استرجاع فرانكفورت اصطناعية موسّعة وإعادة نفس الأرشيف: 141 جدولاً و17 فحص سلامة؛ 3375 عنصر TOC في الحالة الموسّعة، دون إسقاط أو تكرار.
- اختبار سلبي فعلي على أرشيف اصطناعي فقط: تغيير التوقع المحفوظ لعدد orders وبصمته وإعداد الدور. رفضه الاسترجاع بكود RESTORE_TABLES_DIFFER، دون تصحيح أو إنجاح زائف. يشترط اختبار CI حفظ التقرير الخاص، وإظهار RESTORE_ROLES_DIFFER أيضاً، دون العلامة الاصطناعية أو قيم البصمات والإعدادات.
- جلسة Windows المحلية غير مرتفعة الصلاحية؛ رفض الحفظ المحمي فيها متوقع ومعلن. اختبار Linux في CI يُلزم حفظ الملف والتحقق من تنقيحه وصلاحيات المجلد 700 والملف 600. لا ادعاء بأن جلسة الوكيل اختبرت حفظ Administrators-only مرتفعة الصلاحية أو قرأت ملف المالك.

## أمر المالك بعد الموافقة والدمج وتحديث main

**Restore فقط. لا يلزم Backup جديد أو Setup أو تغيير passphrase.** افتح PowerShell كمسؤول:

```powershell
Set-Location C:\Users\TOP\mahdi-admin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/operations/frankfurt-backup-owner.ps1 -Mode Restore -Apply
```

إذا فشل، أرسل diagnostic ثم ملف comparison-sanitized.json من المسار المسجل في restore-local.json فقط. لا ترسل source-evidence الخام أو الأرشيف أو أسرار التشفير. لا يوجد ادعاء بنجاح استرجاع نسخة فرانكفورت الفعلية من التجربة المحلية.
