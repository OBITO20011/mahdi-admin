# مراقبة أخطاء الواجهة — إعداد المالك يوم التشغيل

الحزمة تجهز الإدارة والمتجر فقط. لا حساب Sentry منشأ ولا اختبار مرسل ضمن العمل المحلي. Replay وTracing مطفآن؛ DSN المفقود يعطل الإرسال. التطوير المحلي وisolated لا يرسلان.

1. أنشئ حساباً على sentry.io، واختر الخطة المجانية المتاحة بعد مراجعة حدودها وقت الإعداد. أنشئ مشروع React للإدارة وآخر للمتجر. أضف المطوّر كمستلم تقني؛ لا تضف صاحب المحل لقواعد الأعطال.
2. من Project Settings → Client Keys (DSN) انسخ DSN. استخدم مشاريع أو Client Keys مستقلة للتجربة والإنتاج وstaging. لا تعِد استخدام مفتاح بيئة في أخرى.
3. في جلسة بناء الإدارة أو المتجر، أو ملف محلي متجاهل خاص بتلك الواجهة، ضع المتغير المناسب فقط:
   - `VITE_SENTRY_DSN_PRODUCTION`
   - `VITE_SENTRY_DSN_PRELAUNCH_TRIAL`
   - `VITE_SENTRY_DSN_STAGING`
   DSN عام تقنياً؛ سياسة المشروع إبقاؤه خارج Git. لا تضع Auth Token أو كلمة مرور في VITE. لا ترفع source maps بهذه الحزمة.
4. استعمل سياق البناء المعتمد وverify-dist لكل واجهة؛ تتولد CSP بنطاق ingest المحدد وحده. لا تضف wildcard. البناء المخالف يرفض DSN بدلاً من طباعته. SHA يؤخذ من أمر البناء؛ للإدارة `NAWASRAH_ADMIN_RELEASE_ID` وللمتجر `NAWASRAH_STORE_RELEASE_ID`، أو SHA منصة البناء.
5. في Sentry → Alerts أنشئ قاعدة خطأ جديد أو regression ترسل إلى بريد المطوّر وحده. راجع Rate Limits والحصة. Telegram اختياري عبر تكامل يديره المطوّر داخل Sentry، وليس بوت صاحب المحل؛ لا توجد أسرار Telegram أو خدمة إرسال جديدة هنا.
6. بعد نشر معاينة محمية بتفويض مستقل، افتح DevTools على كمبيوتر المطوّر ونفّذ خطأ واحداً خالياً من البيانات: `setTimeout(() => { throw new Error('SENTRY_OWNER_TEST'); }, 0)`.
7. تحقق من حدث واحد بالبيئة وSHA الصحيحين، ورسالة عامة `FRONTEND_ERROR`. لا اسم زبون أو هاتف أو مبلغ أو query أو سلة أو جلسة. تحقق من وصول التنبيه للمطوّر. لا تنفذ الاختبار في صفحة صاحب المحل أو وسط بيع.
8. إن لم يصل الحدث، افحص DSN/سياق البناء وCSP والحصة من جهاز المطوّر، دون توسيع الصلاحيات أو إرسال بيانات أعمال.

التنقية تبني حدثاً جديداً بقائمة مسموحة: البيئة، SHA، كود ثابت، شاشة معروفة، ومكوّن boundary معروف. تُحذف الرسائل الأصلية وstack frames والحقول وbreadcrumbs والسياقات والطلبات والمستخدم. ذلك يقلل تفاصيل التشخيص عمداً لحماية البيانات. لا يضمن SDK كشف كل تجمد أو تعطل نظام التشغيل؛ اختبار الشاشة البيضاء والخطأ غير المعالج مطلوب قبل التشغيل.

المراجع الرسمية: [إعداد React](https://docs.sentry.io/platforms/javascript/guides/react/)، [تنقية البيانات](https://docs.sentry.io/platforms/javascript/guides/react/data-management/sensitive-data/).


الملفات المحلية المقصودة (متجاهلة من Git): للإدارة `C:\Users\TOP\mahdi-admin\.env.production.local`، وللمتجر `C:\Users\TOP\mahdi-admin\customer-web\.env.production.local`. استعمل `.env.prelaunch-trial.local` أو `.env.staging.local` للبيئة المقابلة، وكل واجهة تأخذ DSN مشروعها الخاص. لا تحفظ مفاتيح الواجهتين في جلسة بناء واحدة؛ متغيرات الجلسة تتغلب على الملفات. يحظر البناء إعادة استخدام DSN نفسه لبيئتين عند توفير القيمتين معًا.

كل بناء له SHA: أوامر السياق تضبطه، والبناء المباشر يستخرجه من Git إذا غاب متغير الإصدار. اختبار المتصفح المحلي القابل للإعادة: `node scripts/testing/run-sentry-browser.mjs`؛ يستعمل بيانات وهمية وإرسالًا معترضًا داخل المتصفح، ولا يتصل بخدمة Sentry أو Supabase.

توافق أدوات217: أدلة الجداول وRPC الحالية مقاسة محليًا من جديد. تحفظ نسخة أدلة217 السابقة دون تعديل، ولا يقبل مرجع217 السابق إلا بعد تطابق أدلة المصدر الحالي وفحوص الكتالوج وACL، ومع إسقاط تغييرات الواجهة المعروفة ببصمتها الدقيقة فقط. لا تغيير للـmigration أو للمنح أو لأي حساب مالي.
