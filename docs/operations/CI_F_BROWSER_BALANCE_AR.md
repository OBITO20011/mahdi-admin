## concurrency وحماية main

الإلغاء محصور في `pull_request`. مجموعة PR ثابتة لرقمه حتى يُلغى التشغيل الذي استُبدل، بينما main وmanual يأخذان مجموعة مستقلة لكل `run_id`، بمقدمة مختلفة للجودة والاسترجاع.

تعطيل `cancel-in-progress` وحده لا يكفي لمنع إلغاء تشغيل main المنتظر إذا تشارك المجموعة؛ لذلك فُصلت مجموعاته أيضاً. لا يستطيع push أو dispatch جديد إلغاء main الجاري أو المنتظر عبر هذه السياسة. قد تبقى تشغيلات main أكثر في الانتظار عند كثرة الدمج؛ هذا ثمن الحفاظ عليها، ولا يغير الفحوص.

الاختبار ينفذ تعبيرات YAML نفسها على أحداث PR/main/manual ويتحقق من اختلاف مجموعات main، وثبات مجموعة PR، وعدم الاشتراك بين workflow الجودة والاسترجاع. [توثيق GitHub الرسمي](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)، [خيارات Playwright الرسمية](https://playwright.dev/docs/test-cli).
