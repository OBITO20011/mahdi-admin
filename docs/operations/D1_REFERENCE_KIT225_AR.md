# عدّة D−1 لسقف 225

1. قبل النافذة، ثبّت SHA main المطابق لـorigin/main وCI الكامل عليه. شغّل `scripts/operations/d1-reference225-kit.ps1` من checkout المعتمد. أي رفض لتطابق الرأس أو CI أو ملفات المالك يوقف التجهيز.
2. راجع المرشح وتقرير المقارنة fresh/incremental. المطلوب 225/185 و705 دوال عامة و51 خاصة و13 عضواً في Realtime، وفرق كتالوج صفر. مرشح الاختبار للتجربة المعزولة ولا يُثبّت مرجعاً معتمداً.
3. بعد توقيع المالك على البصمة ذات 64 خانة، شغّل `scripts/operations/d1-reference225-install.ps1 -Candidate '<مسار المرشح>' -ApprovedSha256 '<SHA-256 الكامل>' -Workdir '<مجلد العمل المعتمد>'`. طابق بصمة الهدف بعد التثبيت واقرأ تقرير الجاهزية. الأداة تحافظ على المرجع السابق وتتحقق من عدم وجود RESET نشط.
4. احتفظ بالمرجع المختوم حتى نافذة القطع. بعد حماية 225 أعد مطابقة SHA وبصمة الملف، ثم انتقل إلى حجز RESET وفق [خطة القطع](GO_LIVE_CUTOVER_AR.md). إذا تغيّر الرأس أعد تجهيز واعتماد المرشح.

عند تعذر قراءة GitHub تبقى البوابة مغلقة بالرمز `D1_CI_UNVERIFIED_MANUAL_REVIEW_REQUIRED`. يُحفظ `failure.json` في مجلد محاولة جديد تحت D1-candidates حتى إن وقع الفشل قبل البناء؛ الحقل `githubRead` يحوي المسار النسبي ورمز HTTP، أو فئة خطأ الشبكة فقط. لا تُحفظ رؤوس أو حمولات أو رسائل أخطاء خام أو اعتمادات. مرحلة `ci` تعني الفحص الأول، و`ci-recheck` تعني إعادة التحقق المعتادة بعد البناء؛ لا إعادة محاولة تلقائية ولا زيادة مهلة. لا يُنتج اعتماد للمرشح ولا يُلمس المرجع الحالي عند الفشل.
