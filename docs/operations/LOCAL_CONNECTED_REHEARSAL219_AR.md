## الحراس الثابتة

- `rehearsal219-owner-source-pins.json` يثبت بايتات 112 ملفاً: أمر RESET219،و`frankfurt-owner-build.mjs`،ونواة `trial-reset214-core.mjs`،وجميع imports المحلية المتعدية. اختبار `rehearsal219.test.ts` يقارن SHA-256 ويعيد بناء الإغلاق؛أي ملف متغير أو تبعية جديدة يرفض الاختبار. لا تغيير لحراس المشروع/pooler/المستخدم/المنفذ/المنطقة أو لأي SQL/migration.
- Restore المعتاد يبقى `network none`،بلا port أو volume،ويحذف الحاوية وفك الأرشيف في `finally`. التوسعة الوحيدة استدعاء `withRestoredRehearsal219` صراحة من الاختبار: callback **بعد** نجاح المقارنة والفحوص وإغلاق معاملة المقارنة،على نفس النسخة،ثم التنظيف عند النجاح والفشل. لا keep-container أو targetURL في أمر المالك.
- المنفذ داخل الحاوية: Restore العادي يبقى25435. وضع البروفة فقط يستخدم5432 عبر Unix socket بلا نشر منفذ،لكي يعيد `cron.schedule` إنشاء `nodeport=5432` مطابقاً للمصدر. أثبت فحص اصطناعي أن25435 كان يعيد job port25435 مقابل5432 المحفوظ؛لم تُغيّر المقارنة أو تُصحح بيانات cron بعد المقارنة لتخفي الفرق.
- النقل لا يقبل URL؛يقبل فقط سياقاً حياً أصدره Restore نفسه،بمعرّف Docker الكامل وبصمة الأرشيف و219/180 ومشروع فرانكفورت. `WeakSet` يلغي السياق عند مغادرة callback،مع فحص network/mounts. لا يكفي إنشاء كائن مشابه أو إعادة استخدام سياق منتهٍ.
- ملفات فك الأرشيف ولقطة الاحتفاظ محمية للمستخدم الحالي/Administrators قبل الكتابة. لا Auth/MFA أو Vault خام في الأدلة؛النواة القائمة تحفظ بصماتها فقط.
- نقل RESET يعيد stdout وstderr بفاصلين مستقلين؛رسالة NOTICE الأصلية لـ`RESET214_FINGERPRINT` تصل من PostgreSQL كما هي في الذاكرة،ولا تُختلق بصمات أو يُحذف stderr كما في جلسة النسخ القرائية. اختبار lifecycle يطلب البصمة فعلياً. عند رفض حارس التبعيات تُحفظ هوية الكائن فقط،ولا يُتجاوز الحارس.
- cron launcher يبقى `off` حتى عند محاكاة تفعيل صفوف cron؛لا Edge أو Telegram/Push process. القاعدة `network none`،وfetch في المنسق يقبل loopback فقط ويرفض redirects. بناء المتجر يستخدم fixture SEO loopback القائم،وليس قراءة فرانكفورت.

| البيانات | نفس writer/reader XLSX ومحللات وخدمات GoLiveSetup والمنتجات/النكهات والمخزون والشيكات؛استبدال I/O Supabase فقط بنقل الاختبار،مع تنفيذ كل دالة DB الفعلية. ملف الدرج تحضير لحقل فتح الوردية،وليس استيراداً غير موجود |

اختيار مالك ملتبس أو MFA غير موجود أو حارس أعمال رافض ⇐ توقف وقرار مالك؛لا إصلاح للبيانات أو تعديل للنواة لتجاوز ذلك.

## التشغيل المحلي

1. فرع الأداة واختباراته وCI الكامل للمراجعة،دون دمج. المرجع ready219 يُبنى بالأداة المعتمدة على مصادر الواجهة الحالية ولا تُعاد تسمية مرجع قديم.
2. حدد أحدث أرشيف محلي219 وبصمته،وready219،ومجلد أدلة جديد خارج Git.
3. من فرع الأداة،على Windows وبحساب يستطيع قراءة إعداد النسخ المحلي:

```powershell
& .\scripts\testing\run-connected-rehearsal219.ps1 `
 -Archive '<مسار أحدث nwb محلي>' `
 -Reference '<مسار local-reference-through219-ready.json>' `
 -Output '<مجلد أدلة جديد خارج Git>' `
 -ClosedTree '<مجلد الأدلة نفسه>\closed-tree'
```

يفك wrapper كلمة **الأرشيف فقط** عبر DPAPI في الذاكرة ويمسح المتغير عند الخروج. لا يقرأ كلمة DB أو R2 أو Telegram،ولا يتصل بأي مشروع. لا قيم في Git أو argv أو الطرفية. لا تُشغّل أوامر النسخ/المراقبة الحية لاستدعاء هذه البروفة.

4. ينشئ المنسق worktree مؤقتاً من #58 `e1e35a5f`؛يرفض trial build/verify/deploy--check ويثبت إنتاجاً محلياً عبر fixture. لا يدمج #58. يحذف روابط node_modules نفسها قبل إزالة نسخة الاختبار،ولا يجتاز junction.
5. الأدلة `rehearsal.json` و`strict-restore.json` وتقارير النواة وملفات Excel الوهمية. التفاصيل المرحلية والتوقيت لا تُعلن ناجحة إلا بعد التشغيل. لا يُستنتج زمن إدخال المالك الفعلي من سرعة البيانات الوهمية.
