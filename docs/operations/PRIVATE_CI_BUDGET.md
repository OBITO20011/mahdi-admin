## كيف لا نفقد specs متأثرة؟

- diff من before SHA للـpush أو base SHA للـPR؛ fetch-depth=0. فشل تحديد diff
  يُفشل التخطيط، لا يتحول إلى قائمة فارغة. أول push بلا base يرجع لكل المتصفحات.
- إغلاق اعتماد متعدٍ: imports، fixtures، harness HTML، CSS، وruntime imports
  ذات const literal مثبتة بربط TypeScript. parameter/shadow/computed لا يُخمن.
- قائمة ملفات المتصفح من Playwright discovery الحقيقي؛لا تُثبّت أسماء/أعداد
  ولا تفترض أن كل ملف مستقبلي اسمه.spec.ts. فحص التقسيم المحلي الحالي920حالة،
  وليس920رقماًمثبتاًفيالحارس.
- specs التي تحمل اعتماداً ديناميكياً غير مثبت تُضاف احتياطياً. ملف مجهول أو
  محذوف/غير مرتبط، shared config، lockfile، backend أو أدوات الفحص => كل المتصفحات.
- docs-only => لا browser specs؛ **كل الوحدات/الأنواع/lint والأسرار تبقى**.
- نفس مشاريع وإعدادات Playwright، مع F shards المعتمدة1/5–5/5. discovery يحسب
  غير الفارغ منها؛ اتحاد core+shards يطابق قائمة selected بالهوية الكاملة
  (project/file/line/column/suite/title) بلا نقص أو تكرار أو تبديل مشروع.
- لا quota-based skipping ولا `pass-with-no-tests` ولا اختيار الصفحة المحملة.
  إذا التغيير واسع يجري كل المتأثر، حتى لو زاد الاستهلاك.

الفحص الكامل يحتفظ بالحارس أيضاً: اتحاد كامل core+الخمسةshards = كامل
discovery. بوابة full تشترط كل DB matrices، ولا تقبل skipped أو غياب فرع.
بوابة affected تسمح فقط بتأجيل فروع DB/غير المتأثرة المحددة في الخطة؛ ليست
إثبات نشر. التحقق قبل التسليم يبحث عن full ناجح على نفس SHA من push/dispatch،
ويرفض light-only أو SHA قديم أو أي DB matrix ناقصة.

## التفعيل عند التحويل — لم يُنفذ الآن

1. بإذن المالك: تأكد من حصة الحساب ونجاح آخر full/الأسرار، ومن أن المراقبة
   المحلية للتوفر على الجهاز الدائم شغالة ومثبتة، وصلاحيات مراجعة CI الخاصة متاحة.
2. حوّل repo إلى private ضمن مهمة التسليم المعتمدة، ثم في Settings → Secrets
   and variables → Actions → Variables اضبط الإعداد الوحيد المذكور إلىtrue.
3. عطّل workflow `public-uptime.yml` من Actions → Disable workflow (أو
   `gh workflow disable public-uptime.yml`). **لا تحذف الملف**؛ الجدول كل30دقيقة
   يضيف نحو1440job-minute في30يوماً إذا كانت كل مهمة دقيقة، فلا يصلح تركه
   مع هذه الميزانية. تعطيل workflow يوقف manual أيضاً؛ فحص التوفر صار محلياً.
4. حدّث توقعات المراقبة بشأن Uptime المعطل وGitHub الخاص ضمن مهمة التشغيل
   المعتمدة؛ لا تضف token للتقارير أو تغيّر watchdog في هذه المهمة.
5. أثبت docs-only push ثم source push: selected IDs صحيحة، وجميع الوحدات
   والأسرار ناجحة. شغّل full يدوياً علىmain وانتظر نهايته وverify-handoff.
   سجّل زمن كل job على العتاد الخاص وأعد حساب الميزانية قبل اعتماد التفعيل.
   قبل أي نشر جديد اعمل ذلك علىSHAالجديد، لا تستخدم full لوالده.
6. التراجع: احذف variable أو اجعلهاfalse؛ يعود full مع كل push، ويتوقف
   dispatcher الأسبوعي. إعادة Uptime منفصلة بعد قرار المالك؛ repo يبقىprivate.

Branch protection يبقي `Complete quality delivery gate` والأسرار إلزاميين
للدمج. ذلك يقبل affected وفق القرار؛ النشر له بوابة full الإضافية. لا تربط
حماية الدمج بأسماء DB jobs المؤجلة فيlight وإلا لا يمكن الدمج. راجع الربط
بإذن المالك عند التفعيل، ولا تغيّر settings الآن.

**لم تُفعّل variable أو weekly dispatch، ولم يُحوّل repo، ولم يُعطّل Uptime.**
