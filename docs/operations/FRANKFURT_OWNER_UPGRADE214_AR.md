# أمر المالك لترقية 214 ونشر إدارة الموظفين

حالة التسليم: التحقق المحلي وCI للحزمة ز قيد الإكمال؛ لا تشغّل هذه الأوامر قبل تسليم النتيجة النهائية ودمج PR الحزمة. لم يتصل الوكيل بفرانكفورت ولم ينشر شيئاً.

بعد الدمج، من PowerShell داخل `C:\Users\TOP\mahdi-admin`، استخدم نسخة main التي تحتوي الحزمة واعتماداتها. يلزم المرجع المحلي `local-reference-through214-ready.json` ومرجع 212 المحلي داخل مجلد `C:\Users\TOP\NawasrahFrankfurt\nawasrah-fra-001-138`؛ يُبنى مرجع 214 محلياً فقط بالأمر:

```powershell
node scripts/operations/build-acl-reference214.mjs
```

لا يعيد البناء تشغيل أي قاعدة مستضافة؛ ينشئ قواعد Docker مؤقتة ويقارن بناء 214 من الصفر بالترقية 212 ثم 213 ثم 214، مع فحص المنح والمالك والإعدادات. يرفض استبدال مرجع موجود. تقرير البناء يبيّن مساره ونتيجته؛ يجب أن تكون `ok: true` وفروق البناء `0`.

1. المعاينة المحلية:

   ```powershell
   npm.cmd run frankfurt-owner-upgrade214 -- --dry-run
   ```

   تقرأ الملفات المرجعية المحلية فقط، بلا كلمة مرور أو اتصال بفرانكفورت. المتوقع `ok: true` و`remoteWriteAttempted: false`. ظهور 213 و214 في خطة المعاينة لا يعني أن 213 غير مطبقة على فرانكفورت؛ التطبيق يتحقق من التاريخ الفعلي ويستبعد المطبق.

2. التطبيق بواسطة المالك:

   ```powershell
   npm.cmd run frankfurt-owner-upgrade214 -- --apply
   ```

   اكتب المرجع `kzevmysfydaslxcerogt` عند الطلب، ثم كلمة مرور قاعدة البيانات بإدخال مخفي. لا تضع كلمة المرور في الأمر أو ملف؛ يستعملها الأمر في الذاكرة. يقبل تاريخاً مكتملاً حتى 212 أو 213 أو 214 فقط، ويتحقق من الكتالوج والمنح قبل الكتابة. يطبّق الملفات غير المسجلة فقط ثم يسجلها بعد نجاح فحصها. المتوقع `ok: true`، وفروق غير متوقعة `0`، وأوامر مواءمة `0`. لا يمنح صلاحيات جديدة لتجاوز اختلاف في المرجع. إذا رفض اختلافاً فتوقف واحتفظ بمسار التقرير.

3. التحقق الصارم:

   ```powershell
   npm.cmd run frankfurt-owner-upgrade214 -- --verify-only
   ```

   المتوقع `ok: true`، وتاريخ كامل حتى 214، وفروق ACL للدوال والجداول والأعمدة `0`. هذا المسار للقراءة فقط؛ لا يصلح الفروق ولا يعيد تطبيق migration. تحفظ الأدلة تحت مجلد NawasrahFrankfurt.

4. بعد نجاح التحقق ودمج الحزمة، ينشر المالك دالة إدارة الموظفين:

   ```powershell
   npx.cmd supabase functions deploy manage-staff-users --project-ref kzevmysfydaslxcerogt
   ```

   لا تستخدم `--no-verify-jwt`. التغيير يرفض أي متصل ليس مالكاً نشطاً بمستوى AAL2 قبل إنشاء عميل الخدمة أو استدعاء Auth Admin، وتبقى آلية تنظيف الحساب اليتيم لحماية فشل الإنشاء المصرّح به.

214 تحفظ تكلفة POS الدقيقة للأسطر الجديدة وتستعيدها عند الإرجاع؛ التاريخي بلا snapshot يبقى بسلوكه السابق. تصلح روابط الخرائط وحارس قراءة الوردية وترتيب أقفال عكس التحصيل. لا backfill ولا تغيير أسعار أو درج أو ذمم ولا توسيع منح. إن كان المرجع الفعلي مطابقاً لـ213/212 فلا يلزم ملف ACL جديد؛ الاختلاف يمنع التطبيق والتحقق حتى مراجعته.
