# RESET224 — دليل المالك

لا يُنفّذ إلا بتفويض يوم القطع، على قاعدة224 ومرجع224 مثبت عبر
[عدّة D−1](D1_REFERENCE_KIT224_AR.md)، وبعد النسخة الفاصلة واسترجاعها
الصارم والبروفة والتوقيع. أدوات219–222 تبقى لأرشيفاتها وأسقفها.

1. اتبع [خطة القطع](GO_LIVE_CUTOVER_AR.md): أغلق الطلبات وجمّد جميع مصادر
   الكتابة واحفظ حالة حجز التنبيهات. نافذة العمل والاستئناف بعيدة عن03:00
   عمّان. لا تغيّر pg_cron أو صلاحياته لمعالجة فرق.
2. شغّل الخطة المحلية:
   `node scripts/operations/frankfurt-owner-reset224.mjs --plan --workdir '<المجلد>' --reference '<مرجع224>'`.
   أي اختلاف في الرأس أو السقف أو البصمات أو خطة الحفظ ⇒ توقف.
3. المالك المفوّض يستعمل `--dry-run` مع المعاملين و`--owner-id '<UUID>'`.
   يثبت التاريخ184ملفاً وكتالوج224 وACL وpg_cron وAuth/MFA والاحتفاظ.
   بعد توقيع النسخة والخطة فقط يستعمل `--apply` والتأكيد الحرفي المعروض.
   تدخل كلمة مرور DB مخفية؛ لا تُكتب في أمر أو تقرير.
4. يحفظ RESET لقطة الاحتفاظ، ويفرّغ Storage ثم يسقط `sales_lite3` و
   `sales_lite2` و`sales_lite1` ثم `public`، ويعيد184ملفاً والتاريخ
   والمحفوظات. النجاح يتطلب `ok:true` و`complete:true` وصفر فرق
   كتالوج/ACL، مع تطابق Auth/MFA وUUID والمال الخام وpg_net.
5. يعود `full_accounting:true` عمداً. يختار المالك OFF من الشاشة ويوقّع
   **«الوضع OFF مُثبت»** قبل الوحدات والأقسام والاستيراد. جميع العدّادات
   مطفأة والجداول الثلاثة نظيفة؛ لا يضيف ملف الاستيراد كميات.

بعد بدء الإتلاف: تبقى الكتابات مغلقة. احفظ `RESET224_IN_PROGRESS.json`
ولقطة الاحتفاظ والتقارير؛ لا apply جديدة أو حذف علامة أو SQL يدوي.
الاستئناف `--resume` يحتاج المجلد والمالك والمرجع واللقطة أنفسهم. أي كتابة
أجنبية، حتى في جداول العدّاد، تمنع الاستئناف وتعود لقرار المالك.

الإثبات المحلي لهذه المسودة: RESET عادي وثلاث نقاط استئناف ناجحة، ورفض
حجز cron الخاطئ وفشل اللقطة والكتابة الأجنبية، مع احتفاظ صارم. هذه ليست
شهادة للأرشيف الحقيقي أو إذناً بتطبيق مستضاف.
