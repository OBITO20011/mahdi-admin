# ترقية المالك إلى 213 — حزمة ي

يُشغّل المالك هذه الأوامر بعد اعتماد نسخة حزمة «ي» ووجود مرجع `local-reference-through213-ready.json` المحلي في مجلد NawasrahFrankfurt المعتاد. الأوامر مجهّزة فقط؛ لم ينفّذ الوكيل أي اتصال بفرانكفورت أو نشر.

من PowerShell داخل نسخة المشروع المعتمدة:

```powershell
Set-Location C:\Users\TOP\mahdi-admin
npm.cmd run frankfurt-owner-upgrade213 -- --dry-run
npm.cmd run frankfurt-owner-upgrade213 -- --apply
npm.cmd run frankfurt-owner-upgrade213 -- --verify-only
```

1. **dry-run:** يقرأ ملفات ومرجع 212 و213 المحليين فقط. لا يتصل بقاعدة البيانات ولا يطلب كلمة مرور. المتوقع `ok:true`، والترقية المعلّقة `213`، و`remoteWriteAttempted:false`. هذا فحص تجهيز الملفات، وليس ادعاءً عن أحدث حالة لفرانكفورت.
2. **apply:** يطلب كتابة المرجع `kzevmysfydaslxcerogt` ثم كلمة مرور القاعدة بإدخال مخفي في الذاكرة. يفحص سجل الترقية والكتالوج وصلاحيات الدوال والجداول والأعمدة كاملة قبل التنفيذ. يطبّق 213 داخل معاملتها، ويتحقق من نتيجتها، ثم يسجلها بأداة Supabase الرسمية. المتوقع `applied:["213"]` و`recorded:["213"]` و`alignmentCommands:0` و`ok:true`. إن كانت 213 مسجلة ومطابقة بالفعل، فلا يعيد كتابتها.
3. **verify-only:** قراءة فقط في كل جلسة SQL؛ يتحقق من 175 migration، والمرجع، وACL بما فيها service_role وPUBLIC، وsearch_path والسياسات وحالة إيقاف الإشعارات. المتوقع `ok:true` و`catalogUnexpectedDifferenceCount:0` و`applicationAclComparison.differenceCount:0`. أي فرق يمنع النجاح.

يحفظ كل تشغيل تقريره في مجلد NawasrahFrankfurt خارج المستودع. لا تُطبع كلمة المرور ولا تُحفظ. إذا فشلت خطوة، احتفظ بالتقرير ولا تنتقل إلى الخطوة التالية.

## الصلاحيات والصور

لا يلزم أمر ACL إضافي لحالة 212 المطابقة للتحقق الصارم التي أكدها المالك. تسحب 213 المنح المحددة بنفسها، ولا تضيف منح تنفيذ أو كتابة. إذا ظهرت منح قديمة أخرى، يتوقف أمر الترقية قبل التطبيق؛ يُراجع الفرق أولاً ولا يصحّحه بمنح صلاحيات جديدة.

تظل الصور عامة عبر رابطها. الزائر الذي يحاول سرد ملفات `product-images` يحصل على قائمة فارغة وفق RLS؛ لا يحصل على أسماء الملفات. رفع الموظفين المسموحين وتعديل ملفات مجلدهم وحذفها باقٍ. ينبغي أن تُستخدم حسابات الخدمة المخصصة في مهمة نسخ الصور اللاحقة، بدلاً من افتراض أن القائمة العامة متاحة.

## pg_net وحدود الحزمة

يبقى تسجيل امتداد pg_net في public كما أنشأه إعداد Supabase والترقية 033. دوال HTTP الفعلية في net، وتظل إعداداتها ومالكها ومنحها ومهام الإشعارات كما هي. لا تنقل هذه الحزمة الامتداد ولا تعيد إنشاءه؛ نقله قد يغيّر اعتماديات الإشعارات خارج نطاقها. [توثيق Supabase](https://supabase.com/docs/guides/database/extensions/pg_net).

Vite 6.4.4 يعالج [GHSA-587h-7wmj-h5pm](https://github.com/advisories/GHSA-587h-7wmj-h5pm). تشغيل `npm.cmd run dev` يستمع إلى localhost؛ التشغيل المتعمد على الشبكة هو `npm.cmd run dev:lan`. لا علاقة لذلك بإذن نشر المعاينة.

تبقى imports Edge عند supabase-js 2.110.8 وweb-push 3.6.7 مع lock مجمّد لكل دالة؛ لا تنفيذ أو نشر للدوال. [توصية Supabase بإعداد مستقل لكل دالة](https://supabase.com/docs/guides/functions/dependencies).

M01 التقرير السنوي مؤجل إلى ما بعد التشغيل. نقل النسخ والحارس والإشعارات وخطة التحويل H01/M02 مهمة مستقلة تالية لحزمة «ي».
