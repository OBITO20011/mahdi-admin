# إثبات حالة تسلسل pg_net في النسخ والاسترجاع

حزمة مستقلة للمراجعة، بلا migration ولا تغيير RESET219. لم يُشغَّل اتصال مستضاف.

تُضيف النسخ الجديدة بصيغة v2 الدليل `pgNetSequenceState` إلى `database/source-evidence.json`: هوية الامتداد والتسلسل وعمود الملكية، ثم `lastValue` كنص عشري و`isCalled` كقيمة منطقية. قارئ المصدر يستخدم `SELECT` فقط بالصلاحيات القائمة؛ لا منح جديد ولا استهلاك رقم.

بعد استرجاع dump، يتحقق الإصلاح من معرّف حاوية Docker الذي أعاده Restore نفسه، واسمها التابع للعملية، و`network=none` وعدم وجود mounts أو منافذ منشورة. يفتح اتصال socket محلياً إلى الحاوية فقط. لا يقبل URL أو executor من المستدعي. يعيد حالة التسلسل الثابت `net.http_request_queue_id_seq` بـ`setval` بعد تطابق هوية المصدر والهدف، ثم يقرأها ثانيةً. المقارنة الشاملة الأصلية تظل شرط النجاح، بلا استثناء.

النسخ v2 القديمة: قيمة موجبة آمنة في الدليل القديم تُثبت الحالة المستعملة. أما `null` أو غياب الدليل أو اختلاف الهوية أو عدد غير آمن فتُرفض. لا تستنتج أن `null` يعني القيمة الابتدائية: قد يكون التسلسل غير مستعمل بقيمة مختلفة، أو تكون القراءة محجوبة. احتفظ بالأرشيف القديم، وأنشئ نسخة جديدة بالأداة المعتمدة عند قرار المالك. لا تعدّل الدليل داخل أرشيف حقيقي.

`ROLLBACK` يرد صف طلب pg_net، لكنه لا يرد رقم التسلسل؛ لذلك لا يُحذف هذا الفرق من المقارنة. الاختبار يحفظ الحالة الفعلية ثم يعيدها في الحاوية المعزولة.

القبول المحلي المطلوب: غير مستعمل افتراضي وغير افتراضي؛ مستعمل؛ طلب نقل متراجع عنه؛ تكرار نفس Restore؛ رفض هوية أو دليل غير معتمد دون تعديل الحالة؛ ثم نسخة مشفّرة جديدة بعد استخدام التسلسل ← Restore ← مقارنة صارمة. تبقى اختبارات 214–219 وACL والأدوار والبيانات والصور والتنظيف قائمة.

**لا تدمج هذه الحزمة قبل مراجعة Claude.** تحديث الأداة على جهاز المالك وتشغيل نسخة حية جديدة ليسا جزءاً من هذا الإثبات المحلي.
