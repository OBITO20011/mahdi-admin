# RESET222 للمالك — بعد ترقية222 واعتماد مرجع D−1

الأداة مخصّصة لقاعدة222/182 قبل إدخال البيانات الحقيقية، والوضع **ON**. تعيد بناء المخطط الحرفي وتزيل بيانات التجربة مع إبقاء حساب المالك وMFA والفرع/المستودع الرئيسي والقواميس والإعدادات المحفوظة. لا تُستعمل لتصحيح مبيعات أو أسعار بعد التشغيل، ولا على تجربة OFF قائمة. لا إذن تنفيذ أو اتصال مستضاف بهذه الوثيقة.

قبلها: اعتماد222 وCI على SHA النهائي، [ترقية محروسة](UPGRADE222_AR.md) مكتملة مع Backup/Restore/verify-only، ثم [مرجع222 معتمد ومثبت](D1_REFERENCE_KIT222_AR.md). مرجع220 أو مرشح الاختبار غير صالح لهذا المسار. الأرشيفات وأدوات220 تبقى منفصلة ومحكومة بسقفها؛ لا تغيير إلى المرجع السابق يدوياً.

1. اقرأ [خطة القطع](GO_LIVE_CUTOVER_AR.md) وورقتها كاملة. أوقف الكتابات فعلياً وكل الأجهزة والمستهلكات، وأغلق الطلبات. احفظ حالة الحجز الرسمي للتنبيهات؛ لا تخمّن حالات cron أو تعيد إنشاء pg_cron. النسخة الفاصلة واسترجاعها الصارم والبروفة والتوقيع تسبق أي حذف.
2. الخطة المحلية: `node scripts/operations/frankfurt-owner-reset222.mjs --plan --workdir '<مجلد الأداة>' --reference '<local-reference-through222-ready.json>'`. لا اتصال ولا مبالغ دقيقة من القاعدة في plan.
3. المالك أو منفّذ مفوّض صراحةً يشغّل `--dry-run` بالمعاملين السابقين و`--owner-id '<UUID المالك>'`. يثبت القاعدة222 وتاريخها وكتالوجها وACL وهوية pg_cron وMFA والمحجوزات وبصمة المرجع. أي فرق ⇒ توقف؛ لا منح صلاحيات أو نسخ مرجع آخر لتجاوز الحارس.
4. بعد توقيع الخطة والنسخة: `--apply` بدلاً من dry-run، من طرفية المالك بالصلاحية المطلوبة، ثم التأكيد الحرفي الذي تعرضه الأداة. كلمة مرور DB تدخل مخفية ولا تُكتب في الأمر أو ملفات العمل. البداية: لقطة احتفاظ محمية ← تفريغ Storage ← إسقاط مخططات التطبيق فقط ← إعادة182ملفاً وتسجيلها ← إعادة المحفوظات ← مقارنة صارمة.
5. النجاح يتطلب `ok:true` و`complete:true`،182مطبقة ومسجلة،صفر فرق كتالوج/ACL،وحفظ UUID/Auth/MFA والإعدادات وpg_net. الحقل `full_accounting` يعودtrue عمداً. لا تستورد حتى يختار المالك OFF من الشاشة ويوقّع «الوضع OFF مُثبت»؛ بعدها الوحدات والأقسام والملف والدرج0 وفق البطاقة.

الفشل بعد بدء الإتلاف: تبقى الكتابات مغلقة؛ احتفظ بـ`RESET222_IN_PROGRESS.json` ولقطة الاحتفاظ والتقارير. **لا apply جديدة ولا حذف علامة ولا db reset --linked أو DROP/TRUNCATE يدوي.** بعد تشخيص السبب يعتمد المالك `--resume` بنفس المجلد والمالك والمرجع واللقطة. تغير الهوية/المصدر/البصمة أو وجود أعمال حقيقية جديدة ⇒ رفض وصعود إلى قرار المالك وخطة الأرشيف، بلا حذف تلقائي. نافذة العمل وresume تبقى بعيدة عن03:00عمّان كما في البطاقة.
